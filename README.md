# Julia — защищённые заявки на консультации

## Архитектура
- `frontend/index.html` — существующий интерфейс, дизайн и навигация сохранены.
- `backend/app/main.py` — FastAPI для приема заявок и ограниченного просмотра администратором.
- PostgreSQL — заявки с шифрованием имени, контакта и текста (Fernet). Ключи **только** в переменных среды.
- SMTP — обезличенное уведомление о новой заявке; текст и телефон **никогда** не отправляются в письме.

**Заявка не означает подтвержденный сеанс**. Выбор слотов, подтверждение записи, оплата и клиентские аккаунты еще не реализованы.

## Railway (ветка feature/secure-booking-backend)
1. Добавьте PostgreSQL в Railway проект, подключите `DATABASE_URL` через Railway variable reference к БД.
2. Создайте в сервисе `FIELD_ENCRYPTION_KEY` (Fernet), `ADMIN_API_KEY`, `RATE_LIMIT_SECRET`; команды генерации — в `.env.example`. Эти значения не должны попадать в GitHub. **Сохраните резервную копию ключа шифрования в защищенном месте**: при потере расшифровать существующие заявки будет нельзя.
3. Настройте `NOTIFICATION_EMAIL`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`. Для боевого использования настройте почтовый ящик и проверьте SPF/DKIM/DMARC. Без SMTP заявки сохраняются, но письма не приходят: `notification_status=pending`.
4. Railway должен выбрать `Dockerfile`. Домен — Settings → Networking → Generate Domain. Включите HTTPS (Railway custom domain/автодомен).
5. После настройки переменных проверьте `/api/health` и тестовую отправку каждой из трех форм. До этого **не переводите боевой домен** на новую ветку.

### Получение заявок администратором
`GET /api/admin/requests` с заголовком `X-Admin-Key: <ADMIN_API_KEY>`. Например, локально:
`curl -H "X-Admin-Key: $ADMIN_API_KEY" https://YOUR-DOMAIN/api/admin/requests`.
Не передавайте ключ через URL или публичный браузерный код. Удобная админка с отдельной аутентификацией — следующий этап.

## Безопасность и ограничения
- Шифрование данных на уровне приложения, отсутствие секретов в репозитории, SQLAlchemy без SQL-конкатенации.
- Проверка согласия, минимальная валидация, same-origin check, лимит 5 успешных заявок / 15 мин по HMAC-хешу IP. **Это базовая защита, а не гарантия от спама, DDoS, взлома или утечки**.
- Нет клиентских аккаунтов/паролей. Администратор использует серверный API-ключ. На следующем этапе нужны полноценная админка с MFA, аудит доступа, ротация ключей, резервное копирование/восстановление, политики хранения/удаления, масштабируемое ограничение частоты, мониторинг ошибок и внешняя проверка безопасности.
- Текст запроса может содержать сведения о здоровье: нужен отдельный правовой аудит действующей политики, согласия, сроков хранения, договоров с обработчиками, применимых требований к локализации персональных данных (особенно если сайт работает с клиентами в РФ). **Не публикуйте сайт для реального сбора чувствительных данных до правовой и эксплуатационной проверки.**
- Email уведомление не содержит контактов и текста обращения; психолог получает их через защищенный endpoint. Настоящая надежная очередь уведомлений с повторными попытками пока не создана.
